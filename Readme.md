# PythonCICD

PythonCICD is a small FastAPI application that demonstrates a containerized CI/CD workflow with Poetry, Docker Compose, GitHub Actions, Docker Hub, and SSH-based staging deployment.

## Requirements

For native development:

- Python 3.11 or newer (below Python 4)
- Poetry 1.8.2

For containerized development:

- Docker with the Compose plugin

## Native development

Install all dependencies from the repository root:

```shell
poetry install --no-interaction --no-root
```

Run the API with automatic reload:

```shell
poetry run python -m uvicorn src.main:app --host 0.0.0.0 --port 8000 --reload
```

The API is available at `http://localhost:8000`, with interactive documentation at `http://localhost:8000/docs`.

## Docker development

Validate and start the merged development configuration:

```shell
docker compose -f compose.yaml -f compose.dev.yaml config
docker compose -f compose.yaml -f compose.dev.yaml up --build
```

The API is available at `http://localhost:8080`. The development overlay bind-mounts `src/` and `public/` and enables Uvicorn reload.

Stop the application with:

```shell
docker compose -f compose.yaml -f compose.dev.yaml down
```

## API endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/` | Application name, version, message, and environment |
| `GET` | `/health` | Container and deployment health check |
| `GET` | `/items/{item_id}` | Example path and optional `q` query parameter |
| `GET` | `/public/demo.txt` | Static demonstration file |
| `GET` | `/docs` | Swagger UI generated by FastAPI |

## Configuration

- `APP_ENV` controls the environment reported by `/`. It defaults to `UNKNOWN`, is `development` in the development overlay, and is `staging` in the staging overlay.
- `APP_TAG` selects the Docker image tag in Compose and defaults to `latest`.
- `BUILD_ENVIRONMENT` is a Docker build argument. The development build includes development dependencies; other builds omit them.

No `.env` file or database configuration is required.

## Tests and quality checks

Run the test suite:

```shell
poetry run python -m pytest -v
```

Run lint and formatting checks:

```shell
poetry run ruff check .
poetry run ruff format --check .
```

To apply Ruff's safe automatic fixes and formatter locally:

```shell
poetry run ruff check . --fix
poetry run ruff format .
```

## CI/CD and staging

Pushes to the `github-actions-cd-docker` branch, except documentation-only changes, trigger the workflow. It:

1. Installs dependencies and runs tests and Ruff checks.
2. Builds and pushes `rezwanul7/python-cicd:latest` to Docker Hub.
3. Copies the base and staging Compose files to `~/PythonCICD/` on the deployment host.
4. Pulls and starts the staging service.
5. Verifies `http://localhost:8080/health` from the deployment host.

Configure these GitHub Actions secrets:

- `DOCKERHUB_USERNAME`
- `DOCKERHUB_ACCESS_TOKEN`
- `HOST`
- `USERNAME`
- `PRIVATE_KEY`
- `PORT`

The deployment host must have Docker Compose and `curl` installed. To deploy manually from a directory containing both Compose files:

```shell
docker compose -f compose.yaml -f compose.stag.yaml pull
docker compose -f compose.yaml -f compose.stag.yaml up -d --remove-orphans
curl --fail http://localhost:8080/health
```
